# دليل 1: إنشاء مشروع Supabase للتطوير

**الوقت:** نحو 10 دقائق. **التكلفة:** مجاني.
**لماذا هذا أولًا:** دليل Microsoft Entra يحتاج عنوان المشروع الذي يُنشأ هنا.

## الخطوات

1. **فتح الموقع:** https://supabase.com ثم **Start your project**.
2. **إنشاء الحساب:** اختيار **Continue with GitHub** وتسجيل الدخول بحساب `salshangiti-sys`. بهذا لا تُنشأ كلمة مرور جديدة.
3. **المؤسسة (Organization):** عند الطلب، إنشاء مؤسسة باسم `home-kitchen` واختيار الباقة **Free**.
4. **المشروع:** **New project**، ثم:
   - **Name:** `home-kitchen-dev`
   - **Database Password:** الضغط على **Generate a password**، ثم حفظها في مدير كلمات المرور (مثل iCloud Keychain). **لا تُرسل في المحادثة.**
   - **Region:** **Central EU (Frankfurt)**. لا توجد منطقة في الشرق الأوسط، وفرانكفورت من الأقرب لجدة.
   - ثم **Create new project** وانتظار دقيقتين حتى يجهز.
5. **أخذ المعلومات العامة:** من زر **Connect** أعلى الصفحة، أو من **Project Settings ← API Keys**:
   - **Project URL** بالشكل `https://xxxxxxxx.supabase.co`
   - **Publishable key** ويبدأ بـ `sb_publishable_`

## ما يُرسل في المحادثة وما لا يُرسل

| يُرسل في المحادثة (عام بطبيعته) | لا يُرسل أبدًا (سري) |
|---|---|
| Project URL | كلمة مرور قاعدة البيانات |
| Publishable key (`sb_publishable_…`) | Secret key (`sb_secret_…`) |
| | المفتاح القديم `service_role` |

المفتاح العام (publishable) مصمم ليعمل داخل التطبيق على الجهاز، وصلاحياته محكومة بقواعد قاعدة البيانات. أما المفتاح السري فيتجاوز كل القواعد، ولا يوضع إلا في إعدادات الخادم.

## ملاحظات الباقة المجانية

- المشروع يتوقف تلقائيًا بعد أسبوع بلا استخدام. سنضيف طلبًا يوميًا آليًا يمنع ذلك. وإن توقف، يُعاد تشغيله من اللوحة بزر **Restore** والبيانات محفوظة.
- الباقة تسمح بمشروعين نشطين: هذا للتطوير، والثاني لاحقًا للاستخدام الفعلي.

## الخطوة التالية

ربط أداة Supabase على الجهاز بالحساب يتم لاحقًا في الطرفية بطريقة GitHub نفسها: رمز يظهر، ثم موافقة في المتصفح.
